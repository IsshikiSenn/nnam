# nnam 架构

## 模块边界

| 模块 | 职责 |
| --- | --- |
| [`app.asuka`](../app.asuka) | 接收文件选择、拖放和系统打开请求，调用转换包并执行对话框、播报和打开位置等系统操作。 |
| [`workspace_flow.asuka`](../workspace_flow.asuka) | 管理工作区页面、当前操作、反馈和可用的导出动作。 |
| [`workspace.asuka`](../workspace.asuka) | 根据工作区状态渲染曲目信息、进度、结果和提示。 |
| [`converter/`](../converter/) | 独立的 Asuka 包。`NcmConverter` worker 负责打开和导出文件，包内完成 NCM 解析、音频解密与校验、标签写入和批量调度。 |
| [`converter/c/`](../converter/c/) | 提供 AES-128-ECB 和同步文件 I/O，由 [`aes.asuka`](../converter/aes.asuka) 和 [`stream_io.asuka`](../converter/stream_io.asuka) 封装调用。 |

## 导入与导出

1. **打开。** 应用调用 `NcmConverter.open`。worker 打开源文件，解析 NCM 容器，并用音频源验证解密后的 FLAC 或 MP3 边界。解析结果持有该音频源。UI 使用返回的 `NcmSummary` 显示曲目信息和元数据提示。
2. **写入。** 单文件导出复用已打开文件的 worker。批量导出由 [`batch_export.asuka`](../converter/batch_export.asuka) 调度，每项用独立的 worker 打开和导出。两条路径共用 [`writeAudio`](../converter/ncm.asuka)，由已校验的音频格式写入可用标签与封面、流式复制音频并返回格式警告。
3. **发布。** worker 内的[导出文件发布模块](../converter/export_publication.asuka)在创建临时文件前检查源文件，将临时输出交给音频格式模块写入，关闭输出后再次检查源文件。单文件导出重命名到用户所选的路径，可替换已有文件。批量导出使用排他发布，路径被占用时换一个带数字后缀的名称再试。发布模块在退出时尝试清理临时文件，成功发布后返回实际保存路径和格式警告。

## 工作区流程

- 工作区区分导入页、曲目页、批量进度页和批量结果页，并独立记录正在进行的操作。内容区可滚动，底部的原生按钮在窗口变窄时换行。按钮、进度控件和文字沿用平台外观，应用不覆盖系统强调色。菜单、底部按钮和保存处理器共用单曲导出条件。取消对话框会保留当前页面和反馈。确认换曲后读取失败会显示导入页及恢复提示。
- 批量进度和结果保留原曲目，用户返回后可继续导出该曲目。批量结果持有汇总和保存位置，后续操作错误会单独显示。至少一项成功时可在 macOS 打开导出文件夹。

## 批量调度与进度

- [`BatchScheduler`](../converter/batch_scheduler.asuka) 负责队列、在途计数、吞吐采样和结果顺序。[`exportNcmBatch`](../converter/batch_export.asuka) 在主线程按调度决定派发任务，为每项发出 `started` 和 `finished` 事件，并传入单调时钟的完成时刻。新增的并发任务仍挂在批次的 `await all` 任务树中，以传播取消。单项失败作为结果记录，其余任务继续处理，最终按输入顺序汇总。
- 每批从两个并发任务开始，待处理文件充足时逐档试到最多四个。吞吐量按成功导出的源文件字节数除以采样时长计算。采样至少经过 400 ms，成功文件数至少为并发数的两倍，并在成功计数达到并发数的整数倍时评估。升档后等旧档任务收尾，再以首个新档成功完成的时刻为起点，将后续成功任务计入样本。吞吐量提升不足 10% 时退回上一档并结束本批试探。已启动的文件继续写完，空出名额后再派发。
- [`ConverterScreen`](../app.asuka) 在确认输出目录后进入进度页。开始事件将文件加入当前列表，结束事件按序号移除文件并更新成功或失败数。同名或重复选择的文件各自更新。原生进度条以已处理数除以总数为值，并向辅助技术提供计数文字。整批结束后切回结果页并播报汇总。

## NCM 解析与流式处理

[`ncm.asuka`](../converter/ncm.asuka) 校验容器标记和段长度，依次读取密钥、歌曲信息和封面。定位音频起点时会跳过封面帧预留长度和实际图片长度中的较大值，复制封面时按容器内位置读取实际图片的原始字节。

[`AudioSource`](../converter/audio_source.asuka) 绑定源文件句柄、音频起点和密钥流。格式校验、曲目摘要、导出和发布前后复查都复用同一个音频源。曲目摘要使用音频段字节数，批量吞吐采样使用整个 NCM 文件的字节数。

单字节读取、窗口读取和流式复制都按音频相对位置检查范围，并以音频段起点对齐密钥流。单字节读取直接比较打开时记录的音频段长度，供 MP3 逐帧校验使用。窗口读取和复制在音频末尾接受零长度，复制在写入前检查整个请求范围。一次流式复制在连续的 64 KiB 块之间复用解密数组，末尾短块按实际长度写出。

[`music_metadata.asuka`](../converter/music_metadata.asuka) 读取歌名、专辑和歌手。歌手条目可包含不同类型的 ID，显示和导出只使用有效的非空名称，并保留原顺序。歌曲信息缺失、无法解码或超过 4 MiB 时，界面会提示，音频通过校验后仍可导出并迁移可用封面。密钥段上限为 64 KiB。

## 格式校验与标签写入

[`AudioFormat`](../converter/audio_format.asuka) 表示已校验的 FLAC 或 MP3。MP3 分支携带帧和标签布局，由 [`mp3_tags.asuka`](../converter/mp3_tags.asuka) 统一决定标签处置、复制起点和警告。FLAC 校验与标签写入共用元数据链的读取逻辑，需要迁移时从源文件重新读取元数据链。

| 格式 | 打开时 | 导出时 |
| --- | --- | --- |
| FLAC | 检查元数据块与首尾帧，验证首尾帧的 CRC。 | 将可用歌曲信息写入 Vorbis Comment，封面写入图片块，保留压缩音频帧。 |
| MP3 | 检查 MPEG Layer III 帧边界，支持标准码率的 CBR 和 VBR。 | 能更新常见的 ID3v2.3 和 ID3v2.4，或新建 ID3v2.4。需要特殊解析的旧标签原样保留，跳过迁移时给出警告。 |

只有在能可靠定位首个 MP3 帧时，才会移除损坏的前置 ID3，并用可用信息重建标签。FLAC 校验集中于首尾帧，音频中段按原样复制。FLAC 元数据块、单个注释块的条目和 ID3 帧各最多 65,536 项。

校验和标签写入的测试入口见[开发指南](development.md#回归测试)。
